# MechBot 产品规划

> **产品名**：MechBot
> **Telegram**：@MechFiBot
> **定位**：DeFi 借贷多协议清算预警机器人，Telegram + Discord 双平台
> **Slogan**：Stay calm, stay ahead. 链上千变，你只需静观。
> **核心差异**：不做通用钱包追踪（RayBot 的战场），专注"仓位有真实资金的 DeFi 借贷用户"的清算风险预警。

---

## 为什么选清算预警，不做其他方向

| 方向 | 付费意愿 | 竞争 | 留存 |
|------|---------|------|------|
| **DeFi 清算预警（我们做）** | ⭐⭐⭐⭐⭐ 仓位是真金白银 | RayBot 没深做 ✅ | 高，仓位不清就一直用 |
| DEX rug-pull 检测 | ⭐⭐ 土狗玩家不付费 | 已有几个在做 | 低，被坑一次就不玩了 |
| EigenLayer 再质押监控 | ⭐⭐⭐ 用户太小众 | 基本空白 | 中 |

**用户故事**（推广时直接用）：
> "我叫 Ning，自己在 Aave 有仓位，有一次差点被清算，当时根本没有好用的多协议聚合预警工具，所以自己做了 MechBot。"

### 备注：深做方向（先存着，后面再拿出来做）

深做从「这条预警能不能帮人做决定」入手。先不铺协议，把已经跑通的 Aave V3 主网仓位算清楚。

现在的消息只报健康因子。用户要知道的是两件事：价格再跌多少会被清算，以及还多少钱或补多少抵押才能回到安全线。`getUserAccountData` 已有抵押、债务和清算阈值，足够算近似值。健康因子 1.06 时，大致是抵押品价格再跌约 5% 到清算线。预警应长成这样：

```text
健康因子 1.06，阈值 1.50
抵押 $16,693，债务 $13,254
抵押品价格再跌约 5% 到清算线
大约再还 $2,800，健康因子可回到 1.50
```

这是通用钱包追踪不会认真做的计算，也是有真仓位的人愿意一直开着通知的原因。

同一周把发送收干净：只在健康因子跌破阈值时发一次，回到阈值以上再发一条「仓位已安全」。每 5 分钟重发会让人把机器人静音。

这两件在 Aave V3 主网上稳定之后，再把同一套计算铺到 Arbitrum、Optimism 的 Aave，以及 Compound、Morpho。那是把深度复制到更多仓位。

## 第一阶段：MVP V0.1 —— 目标 3 天跑通

**核心思路**：不做账号系统、不做数据库、不接支付。只证明"能把链上健康因子变成 Telegram 消息"。

### 功能清单（就这 3 个）

1. **写死配置**：代码里写死一个要监控的以太坊地址 + 你自己的 Telegram chat_id
2. **读取健康因子**：调用 Aave V3 合约的 `getUserAccountData`，获取 `healthFactor`
3. **发送预警**：健康因子低于 1.2，调 Telegram Bot API 发消息

### 数据接口（免费，不需要 API Key）

```
合约：Aave V3 UI Pool Data Provider
方法：getUserAccountData(address user)
返回：totalCollateralBase, totalDebtBase, healthFactor 等
RPC：使用免费公共节点（Alchemy 免费额度 / Infura 免费额度）
```

### Prompt 模板（直接丢给 Cursor / ChatGPT）

```
用 Go 语言和 go-ethereum，写一个程序：
1. 调用以太坊主网 Aave V3 合约的 getUserAccountData 方法，传入一个钱包地址
2. 解析返回的 healthFactor（注意除以 1e18 转为真实数值）
3. 如果 healthFactor < 1.2，通过 Telegram Bot API 发送预警消息
4. 每 5 分钟执行一次
5. 单文件，不建数据库
```

### 验收标准

在测试网或主网找一个健康因子低于 1.2 的地址，你的 Telegram 在 5 分钟内收到预警消息。

### ⚠️ 避坑

- 这个阶段**不处理**多协议聚合、断线重连、区块重组
- 程序崩了重启就行
- **先拿到正反馈最重要**

## 第二阶段：V1.0 多用户免费版 —— 目标 2 周完成

**核心思路**：从"玩具"变成"产品"，让用户自己能加地址，用免费额度限制，为收费做铺垫。

### 功能清单

**数据库（SQLite，两张表）**：
```sql
Users(telegram_id, ref_by, expire_at, is_premium)
Addresses(address, telegram_id, protocol, min_health_factor)
```

**交互命令**：
- `/start`：注册，支持 Deep Link（`t.me/ZennBot?start=ref_xxx`）解析推荐关系
- `/add 0x...`：添加监控地址（免费用户限 3 个地址）
- `/list`：查看当前监控地址及各协议健康因子
- `/remove 0x...`：删除地址
- `/set_threshold 1.3`：自定义预警阈值（默认 1.2）
- `/status`：查看账户状态和到期时间

**多协议支持**：
- Aave V3（主网 + Arbitrum + Optimism）
- Compound V3
- Morpho Blue

**后台轮询架构**：
```go
// 每 5 分钟从数据库读所有地址
// 维护 map[address][]telegram_id 内存字典
// 并发查询各协议健康因子（goroutine pool 控制并发）
// 触发阈值 → 查字典 → 批量发 Telegram 消息
```

**基础降噪**：
- 同一地址同一协议，1 小时内只发一次预警（防轰炸）
- 健康因子恢复正常后，发一条"仓位已安全"消息

### 验收标准

找 2 个朋友试用，各自加了自己的地址，能独立收到预警，互不干扰。

## 第三阶段：V1.5 商业化 —— 目标第 3-4 周完成

**核心思路**：上线简洁的网页控制台，接入 USDT 收款，上线推荐奖励机制。

### 网页控制台（React，风格参考 RayBot，主打简洁）

- 首页：一句定位、三步说明、价格卡片
- 登录：网页显示 4 位验证码 → 跳到 @MechFiBot 核对后点「确认登录」→ 网页自动进入控制台。无需注册，顺带保证机器人能私聊用户
- 控制台：监控地址（各协议健康因子、风险颜色、更新时间）、添加/删除、预警线、Pro 充值、推荐链接

### 定价方案

| 版本 | 价格 | 权益 |
|------|------|------|
| Starter | 永久免费 | 3 个地址，仅 Aave V3 预警 |
| Pro 版 | 5 USDT/月、12 USDT/季 或 36 USDT/年 | 20 个地址，全协议预警 |

Pro 到期后，超出 3 个的地址暂停预警，Compound / Morpho 只显示不预警。

### 支付接入（USDT 专属充值地址，Creem 以后再接）

1. 每个用户一个永久专属地址，HD 钱包派生（EVM `m/44'/60'/0'/0/i` 同时用于 Ethereum、BNB Chain、Arbitrum；TRON `m/44'/195'/0'/0/i`），服务器只放 xpub
2. 后台每 30 秒扫链：EVM 用 `eth_getLogs` 按收款地址过滤 USDT Transfer，游标记在库里；TRON 用 TronGrid 查最近 48 小时打开过充值面板的地址
3. 到账按金额匹配套餐（≥5 / 12 / 36 USDT → 30 / 90 / 365 天），同一笔转账只记一次；开通/顺延 Pro，Telegram 通知用户；首次付费时推荐人和新用户都自动加天数并收到通知
4. 资金归集在本机用 `cmd/mechwallet sweep` 完成，助记词不上服务器

### 单层推荐奖励（加天数）

| 新用户首次购买 | 推荐人奖励 | 新用户奖励 |
|--------------|-----------|-----------|
| 月付 | +7 天 | +7 天 |
| 季付 | +15 天 | +15 天 |
| 年付 | +30 天 | +30 天 |

触发时机：被推荐人首次付费成功时，双方自动加天数；续费不再奖励。推荐多人付费，奖励累加。

### 验收标准

自己走一遍支付流程，Bot 自动给你升级 Pro，推荐人自动增加天数。

## 第四阶段：V2.0 增长功能 —— 目标第 2 个月


**目标**：降低冷启动门槛，带来自然流量。

### 功能方向

1. **每日仓位播报**：每天早 9 点推送订阅用户各仓位健康因子快照，养成使用习惯
2. **大户仓位公开榜**：抓取链上知名地址（如协议团队、KOL 钱包）的健康因子，每天发一条"今日 DeFi 大户仓位动态"，用于社区推广
3. **多链扩展**：支持 Base、Scroll、zkSync 等 L2 上的 Aave 部署
4. **Discord Bot**：与 Telegram 共用后端，接 Discord API 做同步支持
